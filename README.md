# CA Control для macOS

Предварительная версия настраивает прокси, проверяет фактический выходной IP и определяет тип обычного сетевого подключения macOS. Системный туннель и Kill Switch пока недоступны.

## Профиль прокси

На вкладке «Параметры» введите адрес и порт прокси, логин и пароль. Поддерживаются HTTP, HTTPS и SOCKS5. Адресу без схемы соответствует HTTP. Поле «Ожидаемый IP» можно оставить пустым, чтобы увидеть фактический IPv4 или IPv6.

«Проверить и сохранить» проверяет выход через выбранный прокси и после успеха сохраняет профиль в Связке ключей. Профиль можно проверить ещё раз из «Обзора». Проверка отправляет запрос к `api64.ipify.org`. Учётные данные идут в дочерние процессы через stdin. Журнал хранится в памяти до закрытия приложения.

## Стенд macOS

Для стенда на Mac с Apple Silicon установите [Tart](https://github.com/openai/tart) и выполните в каталоге проекта `macos`:

```sh
/bin/sh scripts/run-lab.sh
```

Скрипт создаёт `CA-Control-Lab` из актуального совместимого образа восстановления Apple или запускает существующую VM с тем же именем. Гостевая система получает обычную сеть через NAT. Каталог `macos` монтируется внутри VM в `/Volumes/My Shared Files/ca-control` только на чтение.

После первичной настройки macOS установите инструменты Xcode и Node.js в гостевой системе. Для сборки скопируйте входные файлы в домашний каталог гостя:

```sh
build_dir=$(mktemp -d "$HOME/ca-control-lab.XXXXXX")
cd '/Volumes/My Shared Files/ca-control'
cp -R app lab native scripts tests package.json "$build_dir"
cd "$build_dir"
```

## Сборка для стенда

В созданном каталоге сборки выполните:

```sh
npm install
npm test
/bin/sh scripts/check-filter.sh
npm run build
```

Сборка компилирует вспомогательный код для `arm64` и `x86_64`, объединяет его через `lipo` и передаёт Electron Builder цель Universal DMG. Готовый образ появится в `dist`. Для распространения за пределами стенда потребуется проверить подпись и нотарификацию Apple.

Приёмка в macOS VM должна подтвердить установку, ввод и повторное чтение профиля после перезапуска, обработку отказа прокси и работу приложения на архитектуре гостя. Проверки системного туннеля и Kill Switch проводят отдельно после их реализации. Реальное распознавание Wi-Fi проверяют на Mac с физическим адаптером.

## Проверка транспорта Xray

На стенде с [Xray 26.11.9](https://github.com/XTLS/Xray-core/releases/tag/v26.11.9) укажите полный путь к бинарнику:

```sh
CA_TEST_XRAY=/absolute/path/to/xray npm test
```

Тест поднимает Xray с одним исходящим прокси и слушателем только на loopback. Он проверяет рабочее HTTP CONNECT-соединение, отказ авторизации и остановку прокси. Контрольный сервер обнаружит прямой запрос, если он возникнет. Учётные данные тестовые, все соединения замкнуты на `127.0.0.1`. Без `CA_TEST_XRAY` выполняются тесты без запуска ядра.

## Сетевой фильтр Claude

Нативный фильтр подготовлен для режима, в котором Claude заблокирован. Модуль политики проверяет идентификаторы Claude Desktop, его помощников и CLI. URL и имена узлов позволяют закрывать известные домены Claude, если macOS передала их фильтру. Соединения других приложений сохраняются. В рабочем приложении расширение пока не устанавливается.

Для интеграции в macOS VM нужно подписать расширение с разрешением Content Filter и активировать его средствами Network Extension. Приёмка охватывает реальные идентификаторы Claude и Cowork, Safari, Chrome и Firefox, TCP и QUIC, уже открытые соединения, а также переходы при выключении и обрыве туннеля. Если macOS передаёт только IP общего CDN, одной проверки имени недостаточно для полной блокировки Claude Web.

### Стендовый пакет фильтра

В гостевой macOS нужны Xcode Command Line Tools, Python 3, установленная в Связке ключей подпись Developer ID Application и два [профиля Apple](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension) одной команды. Идентификаторы профилей: `com.cacontrol.macos.filterlab` для приложения и `com.cacontrol.macos.filterlab.filter` для расширения. Оба должны разрешать Content Filter для System Extension. Профиль приложения дополнительно разрешает установку системного расширения.

Из каталога исходников в гостевой macOS запустите:

```sh
python3 scripts/build-filter-lab.py \
  --identity 'Developer ID Application: имя команды' \
  --host-profile /absolute/path/to/host.provisionprofile \
  --filter-profile /absolute/path/to/filter.provisionprofile \
  --output "$PWD/build/filter-lab"
```

Сборка создаёт и проверяет подпись приложения в заданном каталоге. Для живого теста скопируйте `CA Control Filter Lab.app` в `/Applications` внутри VM, снимите контрольную точку и запустите из терминала гостя:

```sh
lab='/Applications/CA Control Filter Lab.app/Contents/MacOS/ca-filter-lab'
"$lab" status
"$lab" enable
```

Подтвердите запрос macOS в системных настройках. Сравните доступ к Claude Desktop и известным доменам Claude с доступом к обычному сайту и `persistent.oaistatic.com`. После прогона выполните `"$lab" remove` и `"$lab" status`. `remove` удаляет только настройки фильтра этого приложения. Для полного сброса тестовой установки восстановите контрольную точку. Проверка этого пакета относится к режиму блокировки, он пока не управляет туннелем.
